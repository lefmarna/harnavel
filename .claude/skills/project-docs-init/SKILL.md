# Project Docs Initialization

テンプレートリポジトリから展開した新規プロジェクトのドキュメントを初期化するスキル。

## Purpose

このテンプレートは Laravel + Inertia + Docker のひな形であり、展開先プロジェクトごとに `docs/` の内容をカスタマイズする必要がある。このスキルは既存のプロジェクトコンテキスト（`old_docs/` 等）を読み取り、テンプレートの docs 構成を維持しつつプロジェクト固有の情報を反映する。

## Core Principle: Add Only Non-Inferable Information

**コードや既存設定から推測できる情報は追加しない。** 以下の基準で判断する:

- 「この情報がないと AI がミスをするか？」→ No なら追加しない
- 既存コードのパターンから学習できるか？ → Yes なら追加しない
- 標準的なフレームワーク慣習か？ → Yes なら追加しない

例: SSR無効時のSEO対応方法、Eloquentの使い方、認証フローの詳細 → すべてコードから読み取れるため追加しない。

## Prerequisites

スキル実行前に以下を確認する:

1. プロジェクトのコンテキスト情報が `old_docs/` ディレクトリ（または指定されたディレクトリ）にまとめられていること
2. テンプレートの `docs/` 構造がそのまま残っていること

## Input

ユーザーに以下を確認する:

1. **コンテキストディレクトリ**: プロジェクトの既存ドキュメントがある場所（デフォルト: `old_docs/`）
2. **ポート設定**: このプロジェクトで使う Docker ポート（複数プロジェクト並列開発のため、プロジェクトごとにポートを変える運用）

## Workflow

### Step 1: コンテキスト読み取り

コンテキストディレクトリ内のすべてのファイルを読み取り、以下の情報を抽出する:

- プロジェクト名・概要（AGENTS.md / README.md の説明文に使用）
- 技術的な制約や特記事項（Architecture セクションに追記する候補）

### Step 2: docs 更新対象の特定

テンプレートの docs 構成のうち、プロジェクト固有の情報で更新が必要なファイル:

| ファイル | 更新内容 |
| --- | --- |
| `AGENTS.md` | Project Context の説明文をプロジェクト固有に更新。セクション構成は維持 |
| `docs/infrastructure.md` | ポート番号、必要ならデプロイ前提を更新 |
| `.env.example` | ポート番号のデフォルト値を更新 |
| `README.md` | タイトル、冒頭のリード文、概要をプロジェクト固有に更新 |

以下のファイルは**変更しない**:

- `docs/planning.md` — 共通ガイド
- `docs/commands.md` — コマンドのソースオブトゥルース
- `docs/generated/` — 自動生成（編集禁止）

### Step 3: AGENTS.md の更新

現在の AGENTS.md のセクション構成を維持したまま、以下だけを更新する:

**書き換える要素:**

- `# Project Context` の説明文（プロジェクトの目的に合わせる。「starter template」表現を除去）

**維持する要素（そのまま残す）:**

- Tech Stack, Layout, Architecture, Verification, Testing, Reference Docs, Documentation の各セクション構成
- 既存の制約事項（キューワーカー/SSR不可など）

**追加してよい要素（慎重に判断）:**

- プロジェクト固有の制約で、コードから推測できないもの（例: 特定の外部API制限、ビジネスルール）
- Architecture セクションへの追記は最小限に

**追加してはいけない要素:**

- コードを読めばわかる実装パターンの説明
- 標準的なフレームワーク慣習の記述
- 汎用的なベストプラクティスや一般論

### Step 4: README.md の更新

- タイトルをプロジェクト名へ変更
- 冒頭 1-2 段落を、そのプロジェクトが何をするものかに書き換える
- 「テンプレートです」「複数案件へ横展開」など、雛形前提の説明を残さない
- セットアップ手順は実際の利用者向けに維持する

### Step 5: ポート設定の更新

ユーザー指定のポート番号で以下を更新:

- `docs/infrastructure.md` の Local Runtime Topology テーブルと Default local endpoints
- `docs/infrastructure.md` の Environment Variables テーブルの Default 列
- `.env.example` の該当変数

### Step 6: 確認と検証

1. 更新内容をユーザーに提示して承認を得る
2. `pnpm lint:docs` を実行して `docs/` 配下のリンク整合性を確認する
3. `README.md` と `AGENTS.md` を目視で確認し、テンプレート感が残っていないかを確認する
4. コンテキストディレクトリに残った情報で反映漏れがないか最終チェック

## Output

更新完了後、以下を報告する:

- 更新したファイルの一覧と変更概要
- コンテキストから抽出したがどのファイルにも置けなかった情報（あれば）
- 次のアクション推奨（追加確認が必要な項目があれば）
