# Kiro specs without steering documents

The Kiro spec workflow runs without `.kiro/steering/`. Steering's core documents are generated by
reading the codebase, so they are a lossier copy of their own source that agents then read in place
of it. Project-wide context stays in the files the codebase cannot derive instead: `AGENTS.md` for
every-session constraints, `CONTEXT.md` for domain terminology, `docs/generated/boost.md` for
Laravel ecosystem conventions, and these records. The Kiro skills read those.

cc-sdd vendors the skills into `.claude/skills/` and `.agents/skills/`, and owns
`.kiro/settings/templates/` and `docs/generated/specs.md` as well. Re-running cc-sdd restores
steering across all of them; re-apply the removal on a periodic upstream check rather than
reopening the decision. That review is the only occasion on which `docs/generated/specs.md` is
edited by hand, and it is revisited with the rest of the Kiro files rather than on its own; the
standing rule in `AGENTS.md` against editing `docs/generated/` holds everywhere else.
