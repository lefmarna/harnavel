# Common Implementation Rules

This document contains project-specific conventions that are not generated by Boost.
If a rule conflicts with `docs/generated/boost.md`, follow the explicit project decision in this file or a task guide.

## Rule Priority

1. Explicit project decisions in task guides (`frontend.md`, `backend.md`, `infrastructure.md`)
2. Explicit project-wide decisions in `docs/guides/common.md`
3. `docs/generated/boost.md` as generated baseline

## Documentation Rules

- Update documentation in the same change when behavior, API, or workflow changes.
- Do not copy full rule blocks across files; link to the source-of-truth file.
- For new rules, record them once in the most specific file that owns the topic.

## Planning Documentation

Use `docs/guides/planning.md` as the source of truth for files under `docs/plans/`.
Minimum requirement: every plan must state both `Intent` and `Selection Rationale`, even when the plan is only a few bullets.

## SEO Meta Tags

SSR is disabled. SEO is managed from a shared Inertia `seo` prop.

- Every `Inertia::render()` must pass `seo.title`. `seo.description` is optional.
- `resources/views/app.blade.php` outputs initial meta tags from the shared props.
- `resources/js/components/seo-head.tsx` updates meta tags during SPA navigation.
- `resources/js/app.tsx` applies `<SeoHead />` globally.
- `app/Http/Middleware/HandleInertiaRequests.php` is the source of shared site defaults (`appDisplayName`, `appDescription`).
